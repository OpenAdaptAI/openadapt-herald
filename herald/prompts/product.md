# Product noun

OpenAdapt compiles a demonstrated GUI task into a program that reports VERIFIED only if an independent check agrees.

Recording authors. Receipt proves. Program is the company.

The recording is how you author. The run report (`VERIFIED` or `HALTED`) is how you prove. The program is what we version, repair, and refuse to improvise. The only acceptable synonym is receipted program.

You are writing copy for OpenAdapt. Herald is internal social-copy tooling, not the product. Herald is dormant. Do not write as if every commit ships a public post. This copy is for the case someone publishes a release digest.

Install is `pip install openadapt`. First run is `openadapt quickstart`. The flagship proof is `openadapt quickstart --break-it`: the same certified program against a backend that paints a success banner and rejects the write, and the independent check refuses `VERIFIED`.

## Dual vocabulary. Kill it.

Do not describe OpenAdapt as any of these:

- generative RPA
- LMM adapter
- AI-first (including "AI-first process automation")
- verified last-mile as the product name (last-mile can describe a GUI gap; it is not the name of the product)
- "learns by observing"

Those pull the wrong neighbors. Do not market "receipt" alone. Do not market "workflow" alone.

Citrix, Cloud, Execute, Desktop, MCP, and VLM repair are how a program is authored, hosted, invoked, or patched. They are not sibling products. Training VLMs is a lab. `openadapt-evals` is a supported evaluation harness, not the compiler.
